# SIMIPAY (M-PESA) 2.0.2

Fixes an incorrect SSL requirement that could prevent installation on a correctly configured PrestaShop 9 shop or hide M-PESA at checkout.

Earlier packages required `PS_SSL_ENABLED_EVERYWHERE`, which PrestaShop 9 removed. This version checks the native `PS_SSL_ENABLED` setting. HTTPS remains required; no database workaround is needed. The issue affected both manually zipped source folders and the 2.0.1 release ZIP.

## Download and install

1. Download **[kopokopo-2.0.2.zip](https://github.com/simiyu-samuel/Prestashop-Lipa-Na-Mpesa-Module/releases/download/v2.0.2/kopokopo-2.0.2.zip)** from the release assets, rather than GitHub's “Source code” archive.
2. Keep **Shop Parameters > General > Enable SSL** enabled and confirm the store has a valid public HTTPS URL.
3. Open **Modules > Module Manager > Upload a module** and select the ZIP. If an earlier installation failed, retry installation. If already installed, run the offered upgrade.
4. Configure **SIMIPAY (M-PESA)** with your Kopo Kopo sandbox credentials and complete a sandbox checkout.

Requirements remain PrestaShop **9.2.x**, PHP **8.2–8.5**, single store, KES, cURL/JSON/OpenSSL and public HTTPS callbacks. No Composer or source editing is needed. See the [installation guide](https://github.com/simiyu-samuel/Prestashop-Lipa-Na-Mpesa-Module/blob/v2.0.2/docs/installation.md).

## Upgrading

From 2.0.1, this patch needs no schema migration or credential changes. From 2.0.0, the existing 2.0.1 branding upgrade also runs. Back up first; credentials and financial history are retained. For legacy 1.0.0, drain pending requests and follow the full upgrade guide.

## Validation

The regression reproduced the old guard's dependency on the removed key and passes with the fix. A read-only test against real PrestaShop 9.2.0/PHP 8.4.16 accepts SSL-enabled shops with the legacy key absent or stale and rejects disabled SSL. That test changes only process-local configuration caches.

The original demo fixture added the obsolete key and masked the defect; this is corrected in the integration fixture and [validation record](https://github.com/simiyu-samuel/Prestashop-Lipa-Na-Mpesa-Module/blob/v2.0.2/docs/validation.md). A fresh 2.0.2 browser installation/upgrade, client-specific checkout acceptance and controlled production acceptance remain outstanding. This is an installable pre-release.
