# SIMIPAY (M-PESA) 2.0.3

Adds checkout customer-name and shop order-reference metadata to help reconcile Kopo Kopo payment requests with PrestaShop orders. First merchant live-payment feedback is recorded separately from validation of this new change.

## Download and install

1. Download **[kopokopo-2.0.3.zip](https://github.com/simiyu-samuel/simipay-prestashop/releases/download/v2.0.3/kopokopo-2.0.3.zip)** from the release assets, rather than GitHub's “Source code” archive.
2. In **Modules > Module Manager > Upload a module**, upload the ZIP and install or run the offered upgrade.
3. Open **SIMIPAY (M-PESA) > Configure**. Existing credentials are retained; new installations require sandbox configuration first.
4. Complete a sandbox checkout and compare the payment amount, reserved order reference and M-PESA receipt across the shop/provider records before controlled live acceptance.

Optional integrity file: **[kopokopo-2.0.3.zip.sha256](https://github.com/simiyu-samuel/simipay-prestashop/releases/download/v2.0.3/kopokopo-2.0.3.zip.sha256)**. Supported target remains PrestaShop **9.2.x**, PHP **8.2–8.5**, single store, KES and public HTTPS callbacks. No Composer or source editing is needed. See the [installation guide](https://github.com/simiyu-samuel/simipay-prestashop/blob/v2.0.3/docs/installation.md).

## Customer-name reconciliation

The module already sends `subscriber.first_name`, `subscriber.last_name` and `subscriber.email`. New requests now also carry the available checkout `customer_name` and reserved `order_reference` alongside `attempt_id` and `cart_id` in metadata. This uses at most four of the provider's five permitted pairs. The reserved reference is used for a later native order; an unpaid attempt is not an order.

Kopo Kopo controls its transaction dashboard's “Name” display. Its API does not document a guarantee that subscriber names or metadata populate that field. This release improves request context; it does not promise to change the transaction name or backfill old records. The checkout customer may differ from the paying M-PESA account holder. Signature, amount, currency, till and receipt validation remain authoritative.

## Upgrading

From 2.0.0–2.0.2, back up the shop, upload this ZIP and run the offered upgrade. No schema migration or credential reset is required; existing records, pending requests and callback routes are retained. Earlier upgrade steps run when applicable. New metadata applies only to new requests. Do not uninstall to upgrade or repeat an unresolved payment to obtain metadata.

For legacy 1.0.0, drain old requests and follow the complete upgrade guide.

## Validation and limits

On 30 October 2026, the first merchant reported a successful live KES 10 payment. Supplied screenshots show a SIMIPAY order marked Payment accepted and a Kopo Kopo transaction marked Received for the same amount/date. Customer/account and invoice details were also reported to work. The exact installed versions, full environment and receipt equality in the shop payment entry were not supplied with that report. Customer details and raw screenshots are excluded from public release evidence.

That report concerns the earlier client installation, not this new 2.0.3 metadata change. Automated regression checks cover serialized requests in both environments, optional/Unicode names, duplicate initiation and a different named payer. Provider acceptance/display of the added metadata, a fresh 2.0.3 browser installation/upgrade and broader failure/recovery/hosting scenarios remain to be exercised. This remains an installable pre-release; no blanket production certification is claimed. See the [validation record](https://github.com/simiyu-samuel/simipay-prestashop/blob/v2.0.3/docs/validation.md).
