# SIMIPAY (M-PESA) 2.0.1

An uploadable PrestaShop module by **[Samuel Simiyu](https://simiyu-samuel.vercel.app/)**, using Kopo Kopo API v2 for M-PESA checkout.

**Installable pre-release:** real sandbox authentication, failed/successful payments, signed callbacks and native paid-order/receipt creation have been verified on PrestaShop 9.2.0 with PHP 8.4.16. Client-specific checkout, the 2.0.1 visual/upgrade rehearsal and controlled production acceptance remain outstanding. See the [validation record](https://github.com/simiyu-samuel/simipay-prestashop/blob/v2.0.1/docs/validation.md).

## Download and install

1. Download **[kopokopo-2.0.1.zip](https://github.com/simiyu-samuel/simipay-prestashop/releases/download/v2.0.1/kopokopo-2.0.1.zip)** from the release assets. This is the module ready for upload. Do not select GitHub's “Source code” ZIP.
2. In PrestaShop, open **Modules → Module Manager → Upload a module** and select that ZIP.
3. Find **SIMIPAY (M-PESA)**, select **Configure**, enter your sandbox till/client ID/client secret/API key, save and test the connection.
4. Complete a sandbox checkout before configuring production credentials. No Composer, source editing or command-line installation is required for merchants.

Optional integrity file: **[kopokopo-2.0.1.zip.sha256](https://github.com/simiyu-samuel/simipay-prestashop/releases/download/v2.0.1/kopokopo-2.0.1.zip.sha256)**.

## Requirements

- PrestaShop **9.2.x**, PHP **8.2–8.5**, single store and KES.
- PrestaShop's required extensions, including cURL, JSON and OpenSSL.
- HTTPS throughout, outbound HTTPS and public inbound HTTPS callbacks.
- An eligible Kopo Kopo account/till and environment-specific API credentials.
- A carrier covering the customer's delivery zone, group and cart range; Kenya is in Africa by default.

## Included

- Original SIMIPAY branding and **Powered by Samuel Simiyu** portfolio attribution.
- Encrypted secrets, automatic OAuth tokens and sandbox/production separation.
- Signed callbacks, exact financial matching, payment history, guarded order creation and M-PESA receipts.
- Admin reconciliation and a protected scheduler endpoint; unresolved STK requests are not automatically repeated.
- Native installation/upgrade scripts, install instructions, license and authorship credits.

## Upgrading

From 2.0.0, upload the ZIP and run the offered upgrade. The display name changes, while the technical `kopokopo` identifier, credentials and payment/order history remain stable. From legacy 1.0.0, drain pending payments and back up first; credentials must be configured again. Follow the [complete installation and upgrade guide](https://github.com/simiyu-samuel/simipay-prestashop/blob/v2.0.1/docs/installation.md).

The sandbox simulates results without moving real money or sending a phone PIN prompt. Production till credentials must come from Kopo Kopo. This is an independent community module; no official provider endorsement or certification is claimed.
